HANJA CLASSROOM / 설치 워크북02

강의 목표와 전제

목표는 모든 수강자가 강사의 배포 주소를 공동 사용하는 것이 아니라, 자신의 Fork와 Supabase와 Vercel과 Render로 독립 앱을 운영하는 것입니다. 강사의 학생 기록은 제공하지 않습니다.

사전 준비는 참여자 매뉴얼 00–04단계입니다. 처음 가입부터 실제 게임까지 50분에 전원이 완료한다고 약속하지 않습니다. 보조 진행자 1명을 권장합니다.

강의 전 준비

  • 3일 전: 매뉴얼, 가입 안내, 원본 저장소 접근 방법을 전달합니다.
  • 1일 전: 준비 완료 또는 막힌 단계만 확인합니다. 비밀 키, 비밀번호, 로그인 링크를 수집하지 않습니다.
  • 강사용 시연 프로젝트는 별도로 준비합니다. 실제 학생 정보가 있는 운영 대시보드를 투사하지 않습니다.
  • 수강자가 본인 Fork에 접근하고 두 배포 서비스가 그 Fork를 선택하는지 점검합니다.
  • 초보자 1–2명에게 원본 접근부터 새 프로젝트 설치까지 사전 리허설을 요청합니다.
  • 기준 버전을 정하고 강의 직전 main에 검증되지 않은 기능을 추가하지 않습니다.
  • SMTP 제한, 무료 서버 첫 기동, GitHub 앱 권한 때문에 막힐 수 있는 사례를 준비합니다.
  • 원본 저장소와 과거 커밋의 실제 기록·비밀값 노출 여부를 배포 전에 별도로 점검합니다. 이 매뉴얼 작성이 전체 보안 감사의 완료를 뜻하지는 않습니다.

50분 진행표

시간 진행 강사의 확인 질문
00–02 72초 도입 영상과 목표 안내 각자 자기 서비스에 설치한다는 점이 보이나요
02–05 00–04 사전 준비 상태 확인 어디까지 완료했나요
05–15 05 웹과 서버 주소 연결 임시 주소가 실제 주소로 바뀌었나요
15–23 로그인과 폴더 저장 확인 새로고침해도 폴더가 남아 있나요
23–38 10개 조로 역할 교대 실습 QR 입장부터 결과까지 확인했나요
38–45 기록 저장과 문제 해결 완료 게임이 기록에 남았나요
45–50 운영과 업데이트 안내 및 질문 다음 수업 때 사용할 주소를 저장했나요

배포 대기 중에는 다음 설정의 목적을 설명합니다. 앞선 분에게 임의의 추가 업데이트나 여러 방 동시 생성을 시키지 않습니다.

화면에서 같은 말을 사용하기

영상, 매뉴얼, 설명의 번호를 통일합니다.

01 코드 → 02 데이터 → 03 웹 → 04 서버 → 05 연결 → 06 확인

단계가 끝날 때는 “여기까지 됐나요” 대신 구체적인 성공 기준을 묻습니다. 성공한 사람은 다음 버튼을 누르지 말고 대기하도록 안내합니다.

실패한 경우: 단계 번호 기록 → 보조 진행자가 확인 → 오래 걸리면 짝 화면으로 실습 참여 → 강의 뒤 본인 환경 마무리.

강사만 기억할 위험 지점

  • Fork는 코드 사본입니다. Supabase 데이터, 서비스 환경 변수, 로그인 계정은 복사되지 않습니다.
  • /health 정상은 저장 정상의 증거가 아닙니다. 폴더와 완료 게임 기록을 실제로 저장해야 합니다.
  • 통합 SQL에는 최신 랭킹 함수와 ID 시퀀스 권한이 포함되어야 합니다.
  • 첫 Vercel의 임시 서버 주소는 실제 Render 주소로 바꾸고 재배포합니다.
  • 기본 로그인 메일은 조직 팀 주소 및 발송량 제한이 있습니다. 반복 발송을 지시하지 않습니다.
  • 실제 휴대폰 진동과 키보드 동작을 PC 시뮬레이션 결과로 보장하지 않습니다.
  • 기존 운영 프로젝트 삭제, 공개 전환, RLS 해제, demo 인증 사용은 실습 해결책이 아닙니다.
HANJA CLASSROOM / 설치 워크북07

영상 확인 후 제작 범위

사용자 선택: 60–75초 가로 영상, 구성과 문구 먼저 검토, 승인된 구성으로 초안 일괄 제작.

현재 검토안은 72초입니다. 큰 한국어 글자와 여섯 단계 연결만 보여주고 세부 설정 이름과 키는 영상에서 읽게 하지 않습니다. 실제 서비스 화면을 흉내 낸 스크린샷도 쓰지 않습니다.

음성 내레이션은 넣지 않는 안을 제안합니다. 배경음은 아직 확정하지 않았습니다. 조용한 배경음 또는 무음 중 선택 후 제작하며, 상업 음원이나 권리 불명 음악을 임의로 삽입하지 않습니다.
