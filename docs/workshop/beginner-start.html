처음이라면 이 안내부터 시작하세요

코딩을 배우는 시간이 아닙니다. 준비된 게임을 내 계정에 설치하는 시간입니다. 컴퓨터에 Node.js, Git, 개발 도구를 설치하거나 검은 명령창을 열지 않습니다.

중요: 아래 간편 경로는 강사가 vercel.json을 GitHub에 반영하고 새 계정 배포를 점검한 뒤 수업에서 사용합니다. 이 자료를 만들었다고 자동으로 GitHub와 운영 서비스가 변경되지는 않습니다.

먼저 알아둘 말은 다섯 개뿐입니다

화면에 나오는 말 쉬운 뜻 내가 할 행동
Fork 게임 코드의 내 사본 GitHub에서 사본 만들기 버튼 클릭
Deploy 인터넷에서 사용할 수 있게 설치 설정 확인 후 배포 버튼 클릭
Dashboard 내 서비스 관리 화면 로그인 후 프로젝트를 선택
Environment Variables 서비스끼리 연결하는 주소록과 열쇠 이름 칸과 값 칸을 구분해 붙여 넣기
Blueprint 미리 만든 서버 설치 설계도 Render가 명령어를 채우도록 선택

Vercel은 게임 화면, Render는 게임 진행 담당, Supabase는 로그인과 기록 보관함, GitHub는 프로그램 원본을 보관하는 곳입니다. 네 서비스에 같은 프로그램을 네 번 설치하는 것이 아닙니다.

1. 브라우저에 네 개의 탭을 준비하세요

  1. 지금 보는 매뉴얼 탭은 닫지 않습니다.
  2. 브라우저 위쪽 +를 눌러 새 탭을 만듭니다.
  3. GitHub 가입을 열고 본인 이메일로 가입합니다. 이메일 인증을 끝내고 아이디를 확인합니다.
  4. 새 탭에서 Supabase를 엽니다. GitHub 로그인 버튼이 있으면 방금 만든 계정으로 연결합니다.
  5. 같은 방식으로 Vercel, Render를 엽니다.
  6. 어느 서비스인지 헷갈리면 주소창의 github.com, supabase.com, vercel.com, render.com을 확인합니다.

여기까지 성공: 네 서비스 모두 본인 계정의 관리 화면이 보입니다. 가입 확인 이메일이나 사람 확인 화면에서 멈추었다면 그 절차부터 끝냅니다. 유료 결제 화면은 강사에게 확인하고 진행합니다.

HANJA CLASSROOM / 설치 워크북04

2. GitHub에서 내 사본을 만드세요

  1. 강사의 원본 저장소를 엽니다.
  2. Fork를 클릭합니다. Download ZIP은 누르지 않습니다.
  3. Owner가 내 아이디인지 확인합니다.
  4. 이름은 바꾸지 않고 Create fork를 클릭합니다.
  5. 주소가 github.com/내아이디/hanja-classroom-workshop로 바뀌었는지 확인합니다.
  6. 첫 파일 목록에서 render.yaml을 확인하고, apps → web 폴더 안에서 vercel.json을 확인합니다.

여기까지 성공: 내 아이디의 저장소에 설정 파일 두 개가 있습니다. 파일이 없다면 강사에게 먼저 알려 주세요. 이후 Vercel과 Render에서 반드시 이 내 사본을 선택합니다.

HANJA CLASSROOM / 설치 워크북05

3. Supabase에서 빈 보관함을 만드세요

  1. Supabase 탭에서 New project를 클릭합니다.
  2. 조직을 고르라는 화면이면 본인 조직을 선택합니다. 조직이 없으면 무료 요금제를 확인하고 만듭니다.
  3. 프로젝트 이름에 hanja-stroke-battle을 입력합니다.
  4. Database password에 새 비밀번호를 정하고 개인적으로 보관합니다. 이 비밀번호를 나중의 공개 키 칸에 넣지 않습니다.
  5. 가까운 아시아 지역을 고르고 Create new project를 클릭합니다.
  6. 준비가 끝나면 SQL Editor → New query를 클릭합니다.
  7. 상세 매뉴얼의 02 데이터베이스 구조 설치하기 → 통합 SQL 보기와 복사를 엽니다.
  8. SQL 상자의 복사를 누른 뒤 Supabase 탭의 큰 편집 칸을 클릭하고 Ctrl+V를 누릅니다.
  9. 본인 새 프로젝트인지 확인하고 Run을 클릭합니다.
  10. 결과의 tables_ready, ranking_ready, sequence_ready가 모두 true인지 확인합니다.

여기까지 성공: 비어 있는 데이터 표가 만들어졌습니다. 학생 이름이나 점수가 없어야 정상입니다. 오류가 나면 표를 지우지 말고 강사에게 오류 문구를 보여 주세요.

4. Supabase에서 주소와 열쇠를 구분하세요

Project Settings → Data API / API Keys에서 확인합니다. 화면에 따라 Project URL은 Connect 안내에도 있습니다.

찾을 항목 확인 방법 어디에 붙여 넣나
Project URL https://…supabase.co 형태 Vercel과 Render
Publishable key 보통 sb_publishable_로 시작 Vercel과 Render
Secret key 보통 sb_secret_로 시작 Render만

예전 프로젝트는 공개 키가 anon, 비밀 키가 service_role로 표시될 수 있습니다. 서로 바꾸어 쓰면 안 됩니다.

지금 이 HTML에 키를 입력하지 않습니다. 비밀 키를 단체 채팅이나 공유 메모장에 적지 않습니다. 해당 서비스의 설정 칸으로 직접 복사합니다. Secret 키가 보이는 화면은 화면 공유를 끕니다.

5. Vercel에서 게임 화면을 설치하세요

  1. Vercel 탭에서 Add New → Project를 클릭합니다.
  2. 내 아이디의 hanja-classroom-workshop 옆 Import를 클릭합니다.
  3. 목록에 없으면 GitHub 접근 권한 설정에서 이번 Fork를 허용한 뒤 다시 찾습니다.
  4. Root Directory → Edit에서 apps → web을 선택하여 apps/web으로 지정합니다. Include files outside the root directory in the Build Step이 보이면 켭니다. 공유 패키지를 함께 빌드하기 위해 필요합니다.
  5. Framework Preset은 Next.js로 둡니다.
  6. vercel.json이 있다면 Install / Build / Output 명령을 직접 쓰지 않습니다.
  7. Environment Variables를 펼칩니다.
  8. 아래 표의 이름과 값을 한 줄씩 넣습니다. 첫째 칸은 이름, 둘째 칸은 값입니다.
첫째 칸 Name / Key 둘째 칸 Value
NEXT_PUBLIC_SUPABASE_URL 내 Supabase Project URL
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY 내 Publishable key
NEXT_PUBLIC_SERVER_URL https://temporary.invalid
  1. Production에 적용되는지 확인하고 Deploy를 클릭합니다.
  2. Ready가 나타나면 프로젝트의 Domains에서 기본 웹 주소를 복사합니다. https://…vercel.app 형태입니다.

여기까지 성공: 내 웹 주소를 열면 로그인 화면이 보입니다. 아직 게임 연결은 안 되어도 정상입니다. 임시 주소는 7단계에서 한 번 교체합니다. 상세한 칸별 입력 방법은 상세 매뉴얼의 03 Vercel 공개 설정과 첫 배포에 있습니다.

HANJA CLASSROOM / 설치 워크북08

6. Render에서 게임 진행 서버를 설치하세요

  1. Render 탭에서 New → Blueprint를 클릭합니다. 수동 Web Service 경로를 선택하지 않습니다.
  2. 내 Fork를 선택합니다.
  3. 브랜치 main, 파일 render.yaml, 서비스 한 개, 요금제 Free를 확인합니다.
  4. 다음 네 이름 옆의 값 칸을 채웁니다. 명령어는 설계도가 제공합니다.
화면의 이름 붙여 넣을 값
WEB_ORIGIN 방금 만든 내 Vercel 기본 웹 주소
SUPABASE_URL 내 Supabase Project URL
SUPABASE_PUBLISHABLE_KEY 내 Publishable key
SUPABASE_SERVICE_ROLE_KEY 내 Secret key — Render에만 입력
  1. Apply / Deploy Blueprint를 클릭합니다.
  2. Live가 되면 서버 서비스 화면의 https://…onrender.com 주소를 복사합니다.
  3. 새 탭에서 그 주소 뒤에 /health를 붙여 엽니다. ok: true가 보이는지 확인합니다.

여기까지 성공: 서버가 응답합니다. 이 점검만으로 로그인과 기록 저장까지 검증된 것은 아닙니다. 이후 연결할 때는 /health를 뺀 기본 주소를 사용합니다.

HANJA CLASSROOM / 설치 워크북09

7. 주소를 두 군데에서 마무리하세요

먼저 Vercel: 임시 주소를 실제 서버로 바꾸기

  1. Vercel의 내 프로젝트에서 Settings → Environment Variables를 엽니다.
  2. NEXT_PUBLIC_SERVER_URL 행의 편집 메뉴를 엽니다.
  3. https://temporary.invalid를 지우고 내 Render 기본 주소를 붙여 넣습니다.
  4. Production 값을 저장합니다.
  5. Deployments에서 최신 배포의 점 세 개 → Redeploy를 클릭합니다.
  6. 새 배포가 Ready가 될 때까지 기다립니다. 저장만 하면 끝이 아닙니다.

다음 Supabase: 로그인 후 돌아올 웹 주소 지정하기

  1. Supabase의 Authentication → URL Configuration을 엽니다.
  2. Site URL에 내 Vercel 기본 웹 주소를 넣습니다.
  3. Redirect URLs에도 같은 주소를 추가합니다.
  4. Save를 클릭합니다.

여기까지 성공: 임시 주소가 실제 서버 주소로 바뀌었고 로그인 주소도 내 웹 주소입니다. 주소에 따옴표, /health, 강사의 주소를 넣지 않습니다.

HANJA CLASSROOM / 설치 워크북10

8. 휴대폰으로 끝까지 시험하세요

  1. 내 Vercel 웹 주소를 노트북에서 엽니다.
  2. Supabase 조직에 등록한 본인 이메일로 교사 로그인을 시도합니다. 메일을 반복 요청하지 않습니다.
  3. 로그인 후 실시간 연결됨을 확인합니다.
  4. 시험 폴더를 하나 만들고 한자를 저장합니다. 새로고침 후 그대로 남는지 봅니다.
  5. 한자를 선택해 게임 방을 만듭니다.
  6. 휴대폰으로 QR을 찍고 시험 닉네임으로 입장합니다.
  7. 게임을 시작하고 학생 화면에서 실제로 문제를 풀어 끝냅니다.
  8. 교사 기록·랭킹에서 결과를 확인하고 새로고침 뒤에도 남는지 봅니다.

최종 성공: 웹 주소가 열리는 것만이 아니라 로그인·학생 입장·게임 진행·결과 저장까지 확인했습니다.

무료 Render의 첫 기동 대기, 학교 Wi-Fi 품질, 휴대폰 브라우저 차이는 별도로 확인해야 합니다. 이 실습 한 번으로 30대 동시 사용의 무지연을 보장하지 않습니다.

멈췄을 때는 이렇게 질문하세요

‘안 돼요’ 대신 아래처럼 말씀해 주세요. 비밀 키와 비밀번호는 가립니다.

저는 5단계 Vercel입니다. Deploy를 눌렀고 Ready 대신 Error가 나옵니다. 화면의 오류 문구는 ○○입니다.

증상 먼저 확인할 것
내 GitHub 저장소가 안 보임 내 Fork 생성 여부와 해당 서비스의 저장소 접근 권한
Vercel이 명령어를 요구함 Fork의 vercel.json 존재와 Root Directory
Render가 시작 명령을 요구함 New → Blueprint로 시작했는지
로그인 메일이 안 옴 조직 등록 이메일, 스팸함, 기본 발송 제한 — 반복 요청 금지
웹은 열리는데 연결 안 됨 NEXT_PUBLIC_SERVER_URL 교체·재배포와 WEB_ORIGIN
결과 저장이 안 됨 SQL 세 항목 true 여부, Render 서버 키 — 공개하지 말 것

50분 강의에 20명이 모두 처음 가입부터 한다면 인증·배포 대기가 크게 겹칠 수 있습니다. 1–6단계는 사전 준비, 7–8단계는 강의에서 함께 진행하는 것이 안전합니다.
