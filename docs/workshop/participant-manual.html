내 계정으로 한자 게임 설치하기

50분 강의 참여자용 상세 매뉴얼

GitHub · Supabase · Vercel · Render를 처음 사용하는 교사를 위한 안내입니다. 원본 게임 코드를 본인 계정으로 가져오고, 본인의 웹사이트와 실시간 서버를 연결합니다.

가져오는 것: 게임 코드, 기본 한자 데이터, 빈 데이터베이스의 구조.

가져오지 않는 것: 강사의 학생 닉네임, 점수, 게임 기록, 누적 랭킹, 교사 로그인 정보, 비밀 키, 개인 수업 폴더와 문제풀.

설치가 끝나면 본인의 교사 계정에서 수업 자료를 만들고 본인 학생들의 기록을 새로 저장합니다. 기존 데이터베이스를 내보내거나 강사 계정에 접속할 필요가 없습니다.

기준일 2026년 9월 9일 · 기준 코드 a692361 및 문서 2d8ee1e

서비스 화면의 메뉴 이름은 변경될 수 있습니다. 버튼의 위치보다 이 문서에 적힌 메뉴 이름과 성공 기준을 확인하세요. 강의용 원본 저장소 접근 권한은 강사가 사전에 안내합니다.

단계 서비스 내가 만드는 것 끝나면 보이는 것
00 공통 준비 네 서비스의 본인 계정 네 대시보드에 로그인
01 GitHub 게임 코드의 내 사본 내아이디/hanja-classroom-workshop
02 Supabase 로그인과 기록을 담을 빈 DB 표와 보안 규칙 생성 성공
03 Vercel 교사와 학생이 보는 웹 내 웹 주소와 Ready 표시
04 Render 방과 점수를 처리할 서버 Live 표시와 /health 응답
05 주소 연결 웹과 서버 및 로그인 연결 실시간 연결 및 교사 로그인
06 사용 확인 내 수업 자료와 시험 게임 새로고침 후 자료와 기록 유지

순서: 00 준비 → 01 코드 → 02 저장소 → 03 웹 → 04 서버 → 05 연결 → 06 확인

처음 Vercel을 배포할 때는 Render 주소가 아직 없습니다. 임시 주소로 웹을 먼저 만든 뒤, 05단계에서 실제 서버 주소로 바꾸고 다시 배포합니다. 그 전까지 게임이 연결되지 않는 것은 정상입니다.

강의는 모든 가입 절차를 50분 안에 끝내는 과정이 아닙니다. 00–04단계는 사전 준비, 05–06단계는 강의 중 완성과 체험을 권합니다. 사전 준비가 어려웠다면 어느 단계에서 멈췄는지 강사에게 알려주세요.

00 준비물과 안전한 기록

노트북, 인터넷, 이메일을 열 수 있는 휴대폰, 게임 접속용 휴대폰을 준비합니다. 노트북에서 같은 브라우저를 사용하고 각 서비스를 별도 탭으로 열어 두세요.

기록할 값 용도 공유 시 주의
내 GitHub 아이디 내 코드 사본 찾기 비밀값 아님
내 Fork 저장소 주소 Vercel과 Render 연결 비공개 저장소라면 접근 권한 주의
Supabase Project URL 웹과 서버가 DB를 찾음 비밀값 아님
Supabase Publishable key 공개 클라이언트 설정 Secret key와 혼동 금지
Vercel 웹 주소 교사와 학생 접속 내 서비스 주소인지 확인
Render 서버 주소 실시간 게임 연결 웹 주소와 혼동 금지

비밀값은 위 표나 공용 문서에 적지 않습니다. DB 비밀번호와 Supabase Secret 또는 service_role 키는 본인의 비밀번호 관리자에만 보관하세요. Secret 키는 Render의 서버 환경 변수 입력 칸에만 붙여 넣습니다.

하지 않을 일:

  • 비밀 키를 GitHub 파일이나 강의 채팅에 올리지 않기
  • 강사의 Supabase 프로젝트, URL, 키를 그대로 사용하지 않기
  • 화면을 공유할 때 비밀 키 표시를 켜 두지 않기
  • 문제 해결을 위해 기존 표나 프로젝트를 임의로 삭제하지 않기
  • 운영 환경에 demo 인증을 켜지 않기

준비 확인: □ 이메일을 확인할 수 있다 □ 노트북과 휴대폰이 있다 □ 비밀값을 개인적으로 보관할 장소가 있다

00 GitHub 가입과 나머지 서비스 로그인

GitHub 계정 만들기

  1. GitHub 가입을 엽니다. 주소: github.com/signup
  2. 본인 이메일, 비밀번호, 사용할 사용자 이름을 입력합니다.
  3. 사람 확인과 이메일 인증을 본인이 직접 완료합니다.
  4. 로그인 후 오른쪽 위 프로필 메뉴에서 사용자 이름을 확인합니다.
  5. 가능하면 2단계 인증을 설정하고 복구 코드를 개인적으로 보관합니다.

Supabase와 Vercel과 Render 가입하기

  1. Supabase를 열고 가입 또는 로그인으로 들어갑니다. 주소: supabase.com/dashboard
  2. GitHub 로그인 선택지가 있으면 방금 만든 GitHub 계정으로 연결합니다.
  3. Vercel 가입, Render 가입도 같은 방식으로 진행합니다. 주소: vercel.com/signup, dashboard.render.com/register
  4. GitHub 권한 승인에서 저장소 접근 범위를 읽습니다. 선택할 수 있다면 이번에 사용할 저장소만 허용합니다. Fork가 아직 없다면 01단계 후 접근 권한을 추가합니다.
  5. 약관, 사람 확인, 본인 인증, 결제 관련 선택은 본인이 내용을 확인하고 처리합니다.

무료 플랜으로 시작하려는 실습입니다. 유료 플랜이나 카드 등록을 요구하는 화면이 나오면 자동으로 다음 버튼을 누르지 말고 강사에게 확인하세요. 계정 심사와 서비스 정책에 따라 가입 절차가 달라질 수 있습니다.

성공 기준: GitHub, Supabase, Vercel, Render의 본인 대시보드에 각각 로그인되어 있습니다.

01 GitHub에서 내 코드 사본 만들기

Fork는 GitHub 안에 만드는 내 사본입니다. ZIP 다운로드나 컴퓨터로 Clone하기는 이 실습에 필요하지 않습니다.

  1. 원본 저장소를 엽니다. 주소: github.com/goodth777/hanja-classroom-workshop
  2. 오른쪽 위 Fork를 누릅니다.
  3. Owner에서 본인 계정을 선택합니다.
  4. Repository name은 hanja-classroom-workshop으로 둡니다.
  5. Copy the main branch only가 보이면 선택합니다.
  6. Create fork를 누릅니다.
  7. 브라우저 주소가 아래처럼 본인 아이디로 시작하는지 확인합니다.
https://github.com/내아이디/hanja-classroom-workshop
  1. apps, packages, render.yaml, package.json이 있는지 확인합니다.

성공 기준: 저장소 상단에 내 아이디가 있고 원본에서 Fork되었다는 안내가 보입니다.

원본이 404로 보이거나 Fork가 불가능하면 여기서 멈추세요. 강사의 비공개 저장소 접근 권한과 Fork 허용 여부를 확인해야 합니다. 강사의 계정 비밀번호를 받아 로그인하는 방식으로 해결하지 않습니다.

중요: 이후 Vercel과 Render가 연결해야 하는 저장소는 goodth777/...가 아니라 내아이디/hanja-classroom-workshop입니다. 강사의 업데이트를 무조건 바로 배포하지 않고 본인 Fork에서 받아 적용하기 위한 구분입니다.

02 Supabase 프로젝트와 키 준비하기

빈 프로젝트 생성

  1. Supabase 대시보드에서 New project를 누릅니다.
  2. 조직이 없으면 본인의 조직을 만듭니다. 무료 실습의 요금제 선택을 확인합니다.
  3. 프로젝트 이름은 hanja-stroke-battle로 입력합니다.
  4. Database password에는 새롭고 강한 비밀번호를 정해 개인적으로 보관합니다.
  5. 지역은 선택 가능한 가까운 아시아 지역을 고릅니다.
  6. Create new project를 누르고 준비가 끝날 때까지 기다립니다.

주소와 키 구분

  1. Project Settings에서 Data API 또는 API Keys를 찾습니다. 대시보드에 Connect 안내가 있으면 거기서 Project URL을 확인할 수도 있습니다.
  2. Project URL을 기록합니다. 보통 https://프로젝트식별자.supabase.co 형태입니다.
  3. Publishable key를 확인합니다. 새 키는 보통 sb_publishable_로 시작합니다.
  4. Secret key를 확인합니다. 새 키는 보통 sb_secret_로 시작합니다. 이 값은 Render에만 입력합니다.
Supabase에서 보이는 이름 나중에 넣을 곳
Project URL Vercel과 Render 모두
Publishable key 또는 예전 anon key Vercel과 Render 모두
Secret key 또는 예전 service_role key Render 서버만
Database password 개인 보관 이 실습의 환경 변수에 넣지 않음

현재 앱은 Render 변수 이름 SUPABASE_SERVICE_ROLE_KEY에 새 Secret key 또는 기존 service_role key를 사용하는 구조입니다. 변수 이름은 바꾸지 말고 값만 본인 키로 넣습니다.

성공 기준: 새 빈 프로젝트가 준비되었고, 공개 키와 비밀 키의 차이를 구분할 수 있습니다.

02 데이터베이스 구조 설치하기

강사가 제공한 install-new-project.sql은 기존 초기 설정과 최근 기록·랭킹 설정을 순서대로 묶은 파일입니다. 학생 기록을 담은 데이터 덤프가 아닙니다.

  1. 반드시 방금 만든 본인 새 Supabase 프로젝트를 엽니다.
  2. SQL Editor → New query로 이동합니다.
  3. 자료 폴더의 install-new-project.sql을 열어 전체를 복사합니다. 웹 매뉴얼의 ‘통합 SQL 보기’에서도 복사할 수 있습니다.
  4. SQL 편집기에 붙여 넣습니다. begin;부터 마지막 점검 쿼리까지 모두 들어갔는지 확인합니다.
  5. 대상이 새 프로젝트인지 다시 확인하고 Run을 누릅니다.
  6. 결과의 아래 세 항목이 모두 true인지 확인합니다.
tables_ready       true
ranking_ready      true
sequence_ready     true
  1. Table Editor에서 game_results, teacher_character_preferences 표를 확인합니다.

표가 비어 있어도 정상입니다. 교사가 자료를 저장하고 게임을 마치면 그때 본인 데이터가 생깁니다. 퀴즈 문제풀과 수업 폴더는 교사 설정 데이터에 저장되므로, 별도의 ‘폴더 표’가 없어도 됩니다.

성공 기준: SQL 실행 성공과 세 가지 true를 확인했습니다.

오류가 나면 끝부분만 다시 실행하거나 표를 삭제하지 마세요. 현재 프로젝트 이름, 실패한 SQL 줄, 오류 문구를 확인하되 키와 비밀번호는 캡처에서 제외합니다. 기존 앱을 업그레이드하는 프로젝트에는 이 신규 설치 절차를 적용하지 말고 별도 마이그레이션 안내를 따릅니다.

통합 SQL 보기와 복사

새 프로젝트에만 사용하세요. 전체 내용을 한 번에 복사합니다.

-- HANJA WORKSHOP / NEW EMPTY SUPABASE PROJECT ONLY
-- Schema and permissions only. No teacher or student records.
-- Generated from repository schema files; reviewed 2026-09-09.

begin;

-- SOURCE: apps/server/supabase.sql
create table if not exists public.game_results (
  id bigint generated by default as identity primary key,
  character text not null,
  player_count integer not null check (player_count between 1 and 30),
  scores jsonb not null,
  completed_at timestamptz not null,
  created_at timestamptz not null default now()
);

-- Legacy rows are anonymous. Apply migrations/20260908_game_history.sql after this
-- bootstrap for teacher-private nickname scoreboards and average rankings.
alter table public.game_results enable row level security;

create table if not exists public.teacher_character_preferences (
  teacher_id uuid primary key references auth.users(id) on delete cascade,
  ordered_chars text[] not null default array[
    '木','水','人','十','一','二','三','四','五','六',
    '七','八','九','日','月','山','火','口','大','小'
  ]::text[],
  approved_characters jsonb not null default '{}'::jsonb,
  updated_at timestamptz not null default now()
);

-- Existing single lists migrate lazily to a per-teacher default folder on read.
alter table public.teacher_character_preferences
  add column if not exists folders jsonb;

alter table public.teacher_character_preferences
  add column if not exists active_folder_id text;
alter table public.teacher_character_preferences enable row level security;

drop policy if exists "Teachers can read own character preferences"
  on public.teacher_character_preferences;
create policy "Teachers can read own character preferences"
  on public.teacher_character_preferences
  for select
  using (auth.uid() = teacher_id);

drop policy if exists "Teachers can insert own character preferences"
  on public.teacher_character_preferences;
create policy "Teachers can insert own character preferences"
  on public.teacher_character_preferences
  for insert
  with check (auth.uid() = teacher_id);

drop policy if exists "Teachers can update own character preferences"
  on public.teacher_character_preferences;
create policy "Teachers can update own character preferences"
  on public.teacher_character_preferences
  for update
  using (auth.uid() = teacher_id)
  with check (auth.uid() = teacher_id);

-- SOURCE: apps/server/migrations/20260908_game_history.sql
-- Existing anonymous records remain untouched and cannot be assigned to a teacher.
alter table public.game_results add column if not exists result_key uuid;
alter table public.game_results add column if not exists teacher_id uuid references auth.users(id) on delete cascade;
alter table public.game_results add column if not exists game_mode text;
alter table public.game_results add column if not exists status text not null default 'completed';
create unique index if not exists game_results_result_key on public.game_results(result_key);
create index if not exists game_results_teacher_mode_date on public.game_results(teacher_id, game_mode, completed_at desc);
alter table public.game_results enable row level security;
revoke all on public.game_results from anon, authenticated;
grant select on public.game_results to authenticated;
grant all on public.game_results to service_role;
drop policy if exists teacher_read_own_results on public.game_results;
create policy teacher_read_own_results on public.game_results for select to authenticated using ((select auth.uid()) = teacher_id);

create or replace function public.teacher_result_leaderboard(p_teacher_id uuid, p_game_mode text)
returns table(nickname text, average numeric, games bigint, rank bigint)
language sql stable security invoker set search_path = '' as $$
  with averages as (
    select s->>'nickname' as nickname, round(avg((s->>'score')::numeric), 2) as average, count(*) as games
    from public.game_results r cross join lateral jsonb_array_elements(r.scores) s
    where r.teacher_id = p_teacher_id and r.game_mode = p_game_mode and r.status = 'completed'
      and s->>'nickname' is not null
    group by s->>'nickname'
  )
  select nickname, average, games, dense_rank() over(order by average desc) as rank
  from averages order by average desc, nickname;
$$;

  5. 휴대폰으로 QR을 찍고 테스트1 같은 시험 닉네임으로 입장합니다. 학생 계정 가입은 필요하지 않습니다.
  6. 학생은 대기 화면에서 진동·소리 확인을 눌러 봅니다. 미지원 안내가 나올 수 있습니다.
  7. 교사는 참가 인원을 확인하고 배틀을 시작합니다.
  8. 영상과 Ready → 3 → 2 → 1 뒤에 게임이 시작되는지 봅니다.
  9. 학생이 한 획씩 입력합니다. 여러 명이면 본인 차례에만 입력됩니다.
  10. 마지막 획을 마치면 교사와 학생 양쪽에 결과가 보이는지 확인합니다.

성공 기준: QR 입장, 차례, 정답 반영, 마지막 결과까지 양쪽 화면에서 진행됩니다.

50분 강의에서는 2인 1조로 번갈아 교사와 학생 역할을 합니다. 한 분의 서비스를 먼저 확인한 뒤 다른 분의 서비스에서도 반복합니다.

실습용 닉네임으로 생성된 기록은 본인 DB에 새로 저장됩니다. 강사의 실제 학생 기록을 복사한 것이 아닙니다.

06 스피드 퀴즈와 한자 지렁이 확인

뜻음 스피드 퀴즈

  1. 수업 폴더에 최소 4개의 한자를 준비합니다. 예: 木 水 人 十.
  2. 수업 자료 → 퀴즈 문제풀에서 새 문제풀을 만듭니다.
  3. 수업 폴더의 한자를 가져오고, 뜻과 음을 확인해 저장합니다.
  4. 게임 → 뜻·음 스피드 퀴즈에서 문제풀과 출제 수를 선택해 방을 엽니다.
  5. 학생이 입장하면 시작합니다. 각 학생은 자기 속도로 문제를 풉니다.
  6. 타이머, 내 점수, 정답 후 다음 문제 이동, 교사 오른쪽 순위 변화를 확인합니다.
  7. 주관식이 출제되면 키보드와 입력란이 가려지지 않는지도 본인 휴대폰에서 확인합니다.

한자 지렁이

  1. 게임 → 한자 지렁이에서 木 한 자를 선택합니다.
  2. 방을 열어 학생이 입장한 후 시작합니다.
  3. 학생은 자기 화면에서 시작점과 끝점을 연결합니다.
  4. 교사 화면에 개인별 진행 카드와 점수가 나타나는지 확인합니다.
  5. 종료 또는 중단 시 학생 화면이 다음 입장을 할 수 있는 상태인지 확인합니다.

중단 시험: 교사가 게임을 중단하면 학생이 새 방 코드를 입력할 수 있어야 합니다. 새 방에서는 이전 닉네임으로 재입장되는지 확인하세요.

실기기 진동·키보드 동작은 휴대폰과 브라우저의 정책에 따라 다릅니다. PC에서 화면을 줄인 시험만으로 실제 휴대폰 동작을 확인했다고 간주하지 않습니다.

06 기록과 최종 완료 점검

  1. 시험 게임 하나를 끝까지 완료합니다.
  2. 교사 상단의 기록·랭킹을 엽니다.
  3. 방금 한 게임이 지난 게임에 나타나는지 확인합니다.
  4. 해당 게임 종류의 평균 점수 랭킹을 확인합니다.
  5. 페이지를 새로고침한 뒤에도 기록이 남아 있는지 확인합니다.

같은 교사 계정 안에서 같은 닉네임을 기준으로 집계합니다. 게임 종류별로 평균을 구분하며, 중단 기록은 완료 게임 평균에서 제외됩니다. 시험을 중단하기만 했다면 평균 랭킹이 비어 있을 수 있습니다.

  • 내아이디의 Fork를 Vercel과 Render가 사용한다.
  • 통합 SQL 점검 결과 세 항목이 true다.
  • Render /health에서 ok가 true다.
  • Vercel 임시 서버 주소를 실제 주소로 바꾸고 재배포했다.
  • 교사 로그인과 실시간 연결이 성공했다.
  • 새로고침 후 수업 자료가 남아 있다.
  • 휴대폰 QR 입장과 마지막 획 또는 문제 완료를 확인했다.
  • 게임 중단 후 방 코드로 다시 들어갈 수 있다.
  • 완료 게임 기록이 새로고침 후에도 남아 있다.
  • 비밀 키와 학생 기록을 GitHub 또는 공용 문서에 올리지 않았다.

모두 확인했다면 독립 설치 완료입니다. 실제 수업 전에는 해당 교실 Wi-Fi와 학생 기기로 추가 점검하세요. 이 체크리스트만으로 30대 휴대폰의 무지연 동작을 보장하지 않습니다.

문제가 생겼을 때 확인 순서

서버 연결이 계속 복구 중

  1. Render 서비스가 Live인지 확인합니다.
  2. /health에서 JSON 응답이 나오는지 확인합니다.
  3. Vercel NEXT_PUBLIC_SERVER_URL에 임시 주소가 남아 있지 않은지 봅니다.
  4. Render WEB_ORIGIN과 브라우저의 실제 Vercel 주소를 비교합니다.
  5. 환경 변수 변경 후 재배포했는지 확인합니다.

로그인 메일이 오지 않음

  1. 이메일 오타와 스팸함을 확인합니다.
  2. 기본 메일을 쓴다면 본인 Supabase 조직 팀에 등록된 주소인지 확인합니다.
  3. 같은 시간에 반복 요청하지 않습니다. 기본 발송 제한을 확인합니다.
  4. Authentication 로그의 오류 문구를 확인합니다. 계정이나 링크를 공용 채팅에 공유하지 않습니다.

메일 링크가 다른 페이지로 이동

  1. Site URL과 Redirect URLs가 본인의 프로덕션 웹 주소인지 확인합니다.
  2. localhost나 강사의 주소가 남아 있는지 확인합니다.
  3. 로그인 링크를 요청한 브라우저에서 열었는지 확인합니다.

폴더 또는 기록이 저장되지 않음

  1. 서버 응답과 DB 저장은 별개임을 기억합니다.
  2. 통합 SQL을 끝까지 실행했는지 확인합니다.
  3. Render의 Supabase URL과 Secret/service_role 키가 같은 본인 프로젝트의 것인지 확인합니다.
  4. 기록만 실패하면 랭킹 함수와 ID 시퀀스 권한까지 설치되었는지 확인합니다.
  5. 새로고침을 반복하거나 표를 삭제하기 전에 오류 문구를 강사에게 보여줍니다.

배포 실패와 도움 요청하기

Vercel 배포 실패

Deployments → 실패 배포 → Build Logs에서 처음 발생한 오류를 확인합니다. 03단계의 Root Directory, Build Command, Install Command, Output Directory를 비교합니다. 오류를 해결하지 않은 상태에서 같은 배포 버튼만 반복하지 마세요.

Render 배포 실패

서비스의 Logs / Events에서 첫 오류를 확인합니다. 본인 Fork의 render.yaml, main 브랜치, 네 환경 변수의 이름과 값을 확인합니다. Secret 키 대신 Publishable 키를 넣었는지도 봅니다.

강사에게 보여줄 내용

멈춘 단계: 예 04 Render
현재 상태: 예 Deploy failed
오류 문구: 비밀값을 지운 첫 오류
마지막으로 한 일: 예 환경 변수 저장

보여주지 않을 내용: Secret/service_role 키, DB 비밀번호, 로그인 링크 전체, 접근 토큰, 실제 학생 명단.

키가 노출되었다면 캡처만 지우는 것으로 끝내지 말고 해당 서비스에서 키를 폐기·교체하고 서버 환경 변수도 갱신해야 합니다. 강사에게 키 자체를 보내지는 않습니다.

강의에서 해결이 오래 걸리면 현재 단계를 기록하고 짝의 화면으로 실습을 이어갑니다. 본인의 프로젝트를 삭제하고 처음부터 다시 시작하지 않습니다.

강의 뒤 운영과 업데이트

다음 수업 전

  • 본인의 교사 웹 주소를 즐겨찾기에 등록합니다.
  • Render가 대기 상태였다면 첫 기동을 기다리고 실시간 연결을 확인합니다.
  • 수업 폴더를 확인하고 휴대폰으로 짧게 시험합니다.
  • 학교 Wi-Fi의 접속 제한, 휴대폰 진동·키보드, 동시 접속 환경을 확인합니다.
  • 무료 서비스의 Usage와 Billing을 주기적으로 확인합니다. 무료 서비스가 상시 실행이나 전달 지연을 보장하지는 않습니다.

원본 개선 받기

  1. 수업 중이 아닐 때 원본의 변경 안내와 DB 마이그레이션 필요 여부를 먼저 읽습니다.
  2. 내 Fork의 Sync fork → Update branch로 변경을 받습니다.
  3. Vercel과 Render의 배포 상태를 확인합니다. 웹 전용 업데이트는 Render 재배포가 생략될 수 있습니다.
  4. DB 변경이 필요한 버전이면 안내된 마이그레이션을 추가로 적용합니다. GitHub 동기화가 DB까지 자동 변경하지는 않습니다.
  5. 짧은 시험 게임과 기록 저장을 다시 확인합니다.

내가 코드를 수정해 충돌이 나면 Discard commits를 누르지 말고 도움을 요청합니다. 환경 변수나 DB 데이터는 Fork 동기화로 강사 값으로 바뀌어서는 안 됩니다.

원본과 데이터 라이선스 및 THIRD_PARTY_NOTICES.md는 유지합니다. 이 자료는 프로젝트를 새로 공개하거나 기존 학생 기록을 이전하는 지시가 아닙니다.
